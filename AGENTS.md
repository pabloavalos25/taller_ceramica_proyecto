# Repository Guidelines

## Project Structure & Module Organization

This repository is currently empty. As source code, tests, documentation, and assets are added, keep them in clearly named directories and document their purpose here. Place tests alongside the code they exercise or in a dedicated `tests/` directory, following the structure established by the project.

## Build, Test, and Development Commands

No build system, test runner, or local development command has been established yet. When adding the first application or package, document its prerequisites and the exact commands to install dependencies, run it locally, and execute its checks.

## Coding Style & Naming Conventions

Follow the conventions of the language and tools introduced to the repository. Use consistent indentation and descriptive names; add formatter and linter configuration when the stack is chosen. Avoid introducing unrelated formatting changes in a functional change.

## Testing Guidelines

Add automated tests for new behavior and regression tests for defects when a test framework is available. Name test files consistently with the chosen framework and document how to run the full suite and an individual test.

## Commit & Pull Request Guidelines

No Git history is available to establish a commit convention. Write concise, descriptive commit messages. Pull requests should explain the change and its motivation, describe the checks performed, and link relevant issues when available. Include screenshots for visible interface changes.

## Security & Configuration

Keep credentials and local secrets out of version control. Document required configuration variables and provide an example configuration with placeholder values when configuration is introduced.
